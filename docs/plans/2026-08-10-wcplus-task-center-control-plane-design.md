# WC Plus 任务中心控制面数据源设计

## 背景

线上 KBase 服务与 macOS 来源 Worker 分开运行。WC Plus 本地 API 只监听 Mac
回环地址，因此线上服务不能通过自己的 `127.0.0.1` 读取 WC Plus 厂商任务。
当前任务中心仍请求 `/api/wcplus/task/all`，会把这一必然的网络边界显示成系统故障。

## 决策

任务中心只展示系统拥有并能可靠解释的两类任务：

- `/api/jobs` 返回的得到电子书后台任务；
- `/api/source-sync/runs` 返回的来源控制面同步运行。

来源订阅由 `/api/source-subscriptions` 提供，用来为同步运行补充来源类型、账号名称
和详情入口。WC Plus 厂商内部任务列表继续保留在本地 API 诊断页，不进入线上任务中心。

## 数据流与降级

页面并行加载书籍任务、同步运行和来源订阅。书籍任务失败时，来源同步运行仍可显示；
来源控制面加载失败时，书籍任务仍可显示。运行记录按订阅映射成中文来源、操作、计数
和错误摘要，点击后回到对应来源控制页。

本次不新增后端 API，不更改 Worker 协议、共享 Token 或升级协议。

## 验收

- 任务中心不再请求 `/api/wcplus/task/all`；
- WC Plus 同步运行可展示账号、操作、状态和处理计数；
- 来源控制面单独失败不会遮蔽书籍任务；
- 原有刷新竞态、离开页面和重试保护继续通过。
