# 得到电子书获取与知识库入库设计

## 目标

在现有规范 Web 路由中恢复一条完整、可验证的个人电子书获取链路：用户在浏览器中扫码登录得到，搜索得到全站电子书，选中有权访问的书籍，创建服务器后台任务，将原始内容下载到服务器配置目录，并自动生成书籍知识包。

首期只恢复电子书。课程和听书后续复用相同的认证与任务框架，不在本次扩大范围。

## 已确认的产品行为

- `/sources/dedao/home` 显示得到登录状态，并提供扫码登录入口。
- `/sources/dedao/ebooks` 保留“我的书架”，新增“全站搜索”模式。
- 搜索结果显示书名、作者、封面、简介、价格和访问状态，不返回上游原始响应。
- 选中电子书后提供两个操作：
  - 主操作“下载并入知识库”：下载 HTML，并在同一任务中生成知识包。
  - 次操作“仅下载”：允许选择 HTML、PDF 或 EPUB。
- 未购买、无访问权限或缺少稳定 `id/enid` 的结果不能创建下载任务，页面展示明确原因。
- 全站结果可在适用时先加入书架，再创建下载或入库任务。
- 页面显示任务的排队、运行、成功、失败状态；关闭页面不取消服务器任务。

这里的“本地”指运行 `kbase-server` 的服务器磁盘，而不是访问网页的浏览器电脑。

## 方案选择

采用“移植既有能力到当前规范 Web”方案：保留当前 `frontend-web/app.js`、规范 URL 和现有知识平台能力，从历史实现中复用经过测试的认证、内容映射、任务持久化与下载入库逻辑。

不直接切回旧版 Vue Web，因为它会替换当前导航与知识平台页面；也不在首期引入浏览器本地 Agent，因为那会增加安装、跨进程认证和网络连通性成本。

## 架构

### 认证

在 KBase HTTP 配置中注入得到认证提供者，暴露 Bearer 保护的接口：

- `GET /api/dedao/session`
- `POST /api/dedao/auth/qrcode`
- `POST /api/dedao/auth/check`

二维码响应只包含本轮扫码所需的短期字段。扫码成功后，服务端沿用现有配置存储保存得到会话；浏览器只接收脱敏用户摘要和登录状态，永不接收 Cookie。

二维码和检查响应设置 `Cache-Control: no-store`。页面在二维码有效期内按固定间隔轮询，成功、过期或请求失败后停止。

### 搜索与书架

扩展得到内容提供者并增加接口：

- `GET /api/dedao/search/ebooks?q=<keyword>&page=<n>&page_size=<n>`
- `POST /api/dedao/ebooks/<enid>/bookshelf`

全站搜索复用已有得到服务层客户端。服务端把上游结果映射为稳定、安全的电子书 DTO，只保留页面需要的字段。书架列表继续使用现有读取接口，两个来源在前端共享结果卡片和分页交互。

空关键词返回空结果，不悄悄回退到书架；上游失败返回明确的 `502`，避免把“搜索失败”显示为“没有结果”。

### 下载与入库任务

恢复持久化任务接口：

- `GET /api/jobs?limit=<n>`
- `POST /api/jobs`
- `GET /api/jobs/<job_id>`

电子书使用两种任务类型：

- `dedao_ebook_download`
- `dedao_ebook_sync_kbase`

创建任务时校验类型、访问标识、下载格式和必填字段。任务先持久化为 `queued`，再由服务器异步执行。服务重启时不能把旧任务误报为成功；中断的 `queued/running` 任务标记为失败并给出可重试原因。

“下载并入知识库”固定先下载 HTML，再调用现有本地提取器生成 `BookKnowledgePackage`。外部 Wiki 编译器不是这条链路的成功前提。

### 存储契约

下载根目录按以下显式配置解析：

1. `DEDAO_DOWNLOAD_ROOT`
2. `DEDAO_KBASE_DOWNLOAD_ROOT`
3. `DEDAO_KBASE_ROOT` 下的相对 `downloads`
4. 知识库根目录相邻的 `downloads`

知识包只写入传给 `kbase-server` 的 `BookKnowledgeStore`，通常由 `KBASE_BOOK_KNOWLEDGE_ROOT` 配置。代码、文档和响应中不写机器专用绝对路径。API 任务结果只提供定位和诊断所需字段；前端不展示完整服务器路径。

## 前端交互

当前静态 Web 保持既有纸张色、橙色强调和信息密度，不引入第二套视觉系统。

- 顶部导航增加账号状态入口。
- 首页在未登录时显示“扫码登录得到”，已登录时显示脱敏昵称及“浏览电子书”。
- 电子书页左侧提供“我的书架 / 全站搜索”切换、搜索框和分页。
- 结果卡片与详情区共享操作状态，避免一次点击创建重复任务。
- 主按钮为“下载并入知识库”；“仅下载”置于次级操作并允许选择格式。
- 任务区显示当前书最近任务；入库成功后直接提供知识包页面链接。
- 对未登录、二维码过期、无权限、缺少标识、上游失败和任务失败分别提供可行动提示。

## 安全与隐私

- 所有 `/api/*` 接口继续要求 KBase Bearer token。
- 得到 Cookie 只保存在服务器配置中，不写入浏览器存储、API 响应、任务记录或日志。
- 二维码短期 token 不写入持久化任务。
- 下载内容和知识包视为个人使用数据，不加入 Git、不写测试样本。
- HTTP 错误不暴露配置文件、下载根目录或知识库根目录的完整路径。
- 系统结构变更后重新生成 `docs/_generated/system-map.json`，不手工维护路由计数。

## 错误处理

- 未配置 KBase token：API 保持 `401`。
- 得到未登录或会话失效：返回可识别的登录错误，前端展示扫码入口。
- 搜索或书架上游失败：返回 `502`，保留原有结果直到用户重试。
- 无购买或访问权限：拒绝创建任务，不产生空任务记录。
- 下载、转换或提取失败：任务进入 `failed` 并记录脱敏阶段信息。
- 成功下载但入库失败：任务仍为 `failed`，保留可重试诊断，不宣称部分成功等于入库完成。

## 测试策略

按 TDD 分层覆盖：

- 服务层：全站搜索请求与安全 DTO 映射。
- HTTP 层：认证、扫码、搜索分页、加入书架、任务创建、任务查询和敏感字段排除。
- 任务层：参数校验、状态迁移、服务器下载根目录、下载成功、入库成功、失败与重启恢复。
- 前端 smoke：规范路由包含登录入口、搜索范围切换、两个操作按钮、任务轮询及成功后的知识包链接。
- 完整验证：相关窄测、`go test ./...`、前端 smoke、前端构建、system-map 漂移检查、隐私检查和 `git diff --check`。

## 成功标准

1. 未登录用户可从得到首页生成二维码并完成登录。
2. 登录用户可搜索得到全站电子书并分页查看结果。
3. 有权访问的书籍可创建“仅下载”或“下载并入知识库”任务。
4. 入库任务成功后，目标书籍出现在现有知识包列表并可直接打开。
5. 页面刷新后仍能看到任务最终状态。
6. 浏览器、日志、API 响应和 Git diff 中不出现得到 Cookie、私密 token、下载内容或机器专用绝对路径。
