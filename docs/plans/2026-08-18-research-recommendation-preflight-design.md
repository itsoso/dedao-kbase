# Research Agent 推荐与运行前检查设计

**日期：** 2026-08-18

**状态：** 已批准

**范围：** KBase Research Web、Research HTTP API、Research Store

**发布边界：** 人工确认后创建研究；不自动发布或修改 Agent Package

## 背景

Research 已能在已发布的 v4 Agent Package 上执行知识库、本地聊天记录和历史研究检索，
并形成带引用的研究案卷。但当前入口要求用户提前知道 Package ID 和版本，也无法在创建前
统一判断知识覆盖、来源权限、Worker 在线状态和预算。结果是底层能力已经可用，普通用户仍会
在创建后才看到参数、策略或运行环境错误。

本设计把 Agent 推荐和运行前检查提升为研究创建的必经步骤。系统自动推荐并预选候选，
解释理由，由用户确认；找不到合格候选时停止创建并引导补全 Agent 或知识。

## 目标

- 根据研究问题、模式和来源，确定性推荐最多三个合格 Agent Package。
- 默认预选第一名，同时保留人工切换和确认边界。
- 在创建前检查 Package、知识覆盖、来源权限、Worker 和预算。
- 对硬错误 fail closed；普通风险只提示。
- 失败或证据不足后创建关联重试，不改写原案卷。
- 保持推荐可解释、可测试、低成本，不依赖模型才能完成。

## 非目标

- 不允许模型绕过 Package、评测、Research Policy 或 Tool Policy。
- 不自动创建、评测、发布或升级 Agent Package。
- 不把所有 Package 技术字段堆到研究入口。
- 不返回文章正文、聊天原文、本地路径、身份信息或凭据。
- 不修改共享 Token 和现有浏览器会话机制，不增加签名协议。

## 方案选择

第一版采用后端确定性推荐服务。前端本地筛选无法可靠判断 Release、策略、Worker 和预算；
完全模型驱动的选择具有成本和不确定性，也不适合作为安全边界。后续可以增加模型辅助重排，
但模型只能在确定性规则筛出的合格候选内调整顺序。

## 总体架构

新增 Research Recommendation and Preflight Service。输入为问题、模式、来源和可选 Package
约束；输出为一个短期 `preflight_id`、整体状态、候选列表、检查结果和缺口建议。

处理分为两阶段：

1. 硬过滤只保留已发布、可信评测通过、schema v4、显式允许 Research，且模式和来源均在
   Research Policy 与 Tool Policy 内的 Package。
2. 对合格 Package 按问题匹配、固定 Release 范围、引用覆盖、更新时间、评测和运行准备度
   进行稳定排序。

预检结果持久化在 Research Store，绑定所有者和规范化请求指纹，建议有效期为十分钟。
用户确认后，创建接口重新检查 Package 哈希、策略、Worker 和预算。任何状态漂移都要求刷新
预检，不使用过期判断启动 Run。

## 确定性推荐

### 合格边界

候选必须同时满足：

- Package 已发布且版本可精确解析；
- Package schema 为 v4；
- 可信评测结果允许 Research；
- `deep_research` capability 与 Research Policy 完整；
- 请求模式和来源是 Policy 允许集合的子集；
- 固定 Release 和引用仍可读取；
- Package 不处于撤回、失效或待替换状态。

### 排序信号

排序使用离散等级和稳定 reason code，不向用户展示虚假的精确百分比。信号包括：

- Package 名称、说明、主题和来源元数据与问题关键词的匹配；
- 固定 Release 中可检索引用对问题术语的覆盖；
- 所选来源是否全部可用；
- 知识更新时间和评测新鲜度；
- Worker 与其他运行依赖是否就绪；
- 保守预算估算是否足以覆盖预计证据和模型调用。

排序结果分为高、中、低匹配。同等级使用规范化 Package ID、版本和内容哈希稳定排序。
候选响应最多返回前三个；第一名默认预选。

### 无候选处理

没有合格候选时整体状态为 `blocked`，不创建 Run。响应把原因归为 Package 缺失、知识覆盖
不足、来源不支持、评测未通过或运行依赖不可用，并提供创建/补全 Agent 的入口参数。系统
不得静默退回全局知识库。

## 数据模型

新增有界预检记录，至少包含：

- `preflight_id`；
- owner scope；
- 规范化请求指纹，不把问题正文写入运行日志；
- 模式与有序来源集合；
- ready/blocked 状态；
- 候选 Package ID、版本、内容哈希、等级和 reason codes；
- 检查结果与缺口 codes；
- 创建和过期时间；
- 可选的关联原 Run ID。

候选摘要使用有界结构，不持久化检索正文。预检记录到期后不能启动 Run，但可以保留最小
审计元数据或按既有保留策略清理。

## HTTP 契约

### `POST /api/research/preflight`

请求包含问题、模式、来源和可选 Package 约束。响应包含：

- `preflight_id` 与 `expires_at`；
- `status`；
- 最多三个候选；
- 每个候选的匹配等级、理由、知识范围、更新时间、评测状态和 readiness；
- 整体 checks、gaps 和 next actions。

所有字符串、数组和请求体沿用 Research 的硬上限。接口按当前浏览器会话或认证 owner 隔离。

### 创建 Research Run

现有创建请求增加 `preflight_id` 和最终选择的 Package 身份。服务端要求：

- owner、问题指纹、模式和来源与预检一致；
- 选择属于固化候选集合；
- Package 版本和内容哈希未变化；
- 所有硬检查仍为通过；
- 创建幂等键重复时返回同一个 Run。

浏览器路径不允许绕过预检。旧机器调用方需要在同一次契约升级中迁移，不能通过可选字段
继续制造创建后失败。

## Web 交互

研究入口由三个紧凑区域组成。

### 问题与范围

用户输入问题并选择模式、来源。满足最小问题边界后，在停止输入约 600ms 时发起预检。
前端取消旧请求或忽略过期响应，慢响应不能覆盖较新的问题。

### Agent 推荐

展示前三个候选。每张卡片显示中文名称、版本、匹配等级、两至三个理由、知识范围、更新
时间、评测状态、支持来源和可运行状态。第一名默认选中，用户可以切换；完整 Package、
Release 和策略信息放在展开详情中。

### 运行前检查

开始按钮前展示：

- Agent Package；
- 知识覆盖；
- Worker；
- 来源权限；
- 预算。

检查结果只有通过、提醒、阻断三种决策状态。阻断时按钮不可用并提供对应处理入口；提醒不
要求逐项确认。页面必须支持键盘操作、明确焦点和窄屏布局。

## 关联重试

失败或证据不足案卷增加“调整并重试”。系统保留原案卷不变，创建带 `parent_run_id` 的新
预检，继承问题、来源和 Package，并根据失败 outcome 给出有界建议，例如扩大时间范围、
启用聊天记录、切换 Agent 或补充知识。新 Run 创建后可以从双方案卷追踪关联关系。

## 错误处理

确定性错误使用稳定 code，并在 Web 映射为中文操作建议：

- `no_eligible_package`；
- `insufficient_coverage`；
- `worker_offline`；
- `source_not_allowed`；
- `budget_insufficient`；
- `preflight_required`；
- `preflight_expired`；
- `package_changed`；
- `readiness_changed`。

策略、范围、预算和持久数据损坏必须直接阻断。网络、临时数据库忙和短暂依赖错误保持可
重试，但不得静默返回空候选或由后台无限重放确定性失败。

## 隐私与安全

- 继续使用现有共享 Token、浏览器会话和 owner scope。
- 预检 API 不返回或记录证据正文、聊天身份、本地 locator、路径或凭据。
- 日志只记录请求指纹、耗时、候选数量和允许的错误码。
- Chatlog 仅在用户选择本地聊天来源时参与 readiness；知识库模式不错误依赖 Worker。
- 创建时重新验证 Research Policy、Tool Policy、来源和 Package 内容哈希。
- 模型重排若后续启用，只能改变合格候选顺序，不能增加候选或修改检查结果。

## 测试与验收

### 规则与 Store

- 覆盖合格过滤、稳定排序、同分处理、候选上限和无候选缺口；
- 覆盖 owner 隔离、过期、跨用户复用、Package 漂移和清理；
- 证明响应和记录不含正文、身份、路径和凭据；
- 证明知识库模式不要求 Worker，聊天来源离线则阻断。

### HTTP 与并发

- 覆盖合法预检到创建、未预检创建、过期和状态漂移；
- 覆盖请求硬上限、未知字段、错误来源和非法 Package 约束；
- 覆盖幂等创建、并发确认和旧响应重放；
- 临时 I/O 错误保持可重试，确定性错误不进入协调器重放。

### Web

- 覆盖防抖、旧请求取消、候选切换、详情展开和检查状态；
- 覆盖中文错误、阻断按钮、焦点、键盘和窄屏；
- 覆盖关联重试继承和原案卷不可变；
- 保留 Package 必填验证，不再创建空任务。

### 真实验收

使用已授权的公众号集合 Agent 和通用合成问题验证：

- 目标 Research Agent 进入第一推荐并显示可解释理由；
- 仅知识库来源不要求 Chatlog Worker；
- 增加聊天来源后显示真实 Worker 状态；
- Worker 离线阻断，恢复后刷新可继续；
- 确认后成功创建 Run，不出现参数无效或空案卷；
- 从历史证据不足案卷创建可追踪的关联重试。

普通预检生产 P95 目标不超过 1.5 秒。性能指标只记录耗时、候选数量和状态，不记录问题或
证据正文。

## 发布与回滚

数据库迁移必须向后兼容。发布按项目 G1-G6 分层执行：合并前完整规则、HTTP、Web、race、
隐私和系统图检查；生产先构建精确 revision，再备份 KBase 二进制和静态 Web 后切换。

回滚恢复旧二进制和 Web。新增预检记录保持可读取或由向后兼容的旧版本忽略，不删除已有
Run。上线验证必须包括公共与 loopback 健康、匿名鉴权拒绝、浏览器真实交互和无敏感日志。

## 成功标准

- 普通用户不需要预先知道 Package ID 或版本即可发起研究。
- 无合格 Agent、Worker 离线、来源越界和预算不足均在创建前被解释并阻断。
- 合格问题展示前三候选并默认选择第一名，用户保留最终确认权。
- 研究失败可通过关联重试继续，原案卷保持不可变。
- 真实线上流程不再产生由缺失 Package 或版本造成的空任务与参数错误。
