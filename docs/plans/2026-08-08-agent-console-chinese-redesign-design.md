# Agent 控制台中文化重设计

## 背景

已发布的 Book Agent 页面把 Package、Agent 与 Book App 共用同一套大幅 Hero。
在 Agent 路由上，英文 package ID 成为最大标题，版本、策略和评测以英文账本
平铺，检索、对话与证据能力则顺序堆叠。桌面端缺少清晰的操作主次，手机端
长 ID 占据首屏，用户难以快速确认 Agent 是否可用、受什么边界约束，以及应从
哪里开始提问。

## 目标

- 将 Agent 路由改造成中文优先的专业控制台，不改变 Package 与 Book App 的现有契约。
- 首屏同时回答三件事：这是哪个 Agent、当前是否可运行、主要操作入口在哪里。
- 桌面端使用“主工作区 + 固定状态栏”，手机端改为单列且不产生横向溢出。
- 保留发布版本、评测、检索策略、模型路由、证据边界和技术身份，降低技术字段的视觉噪声。
- 保持现有检索、对话、阅读、证据、鉴权和运行时 API 行为不变。

## 视觉方向

采用深墨色工业控制台：深色框架表达受控运行环境，米白工作面承载长文本，
酸性绿只表示运行就绪或评测通过，琥珀色只表示待处理或警告。标题使用中文书名
派生的“研究助手”，英文 package ID 退居为 Agent ID。界面不引入装饰性渐变或
卡片墙，依靠紧凑栅格、清晰边线、等宽技术信息和少量状态色形成专业感。

## 信息架构

### 顶部运行带

- 中文标题：优先使用 Release 的书名并追加“研究助手”。
- 次级身份：展示 Agent ID，不再把长 slug 当页面标题。
- 中文路由：包契约 / Agent 控制台 / 阅读应用。
- 状态：版本、运行状态、评测结论和固定 Release 数量。

### 主工作区

- 左侧为操作区：包内检索、循证对话、阅读入口与证据账本。
- 右侧为状态栏：模型路由、检索方式、升级目标、证据边界与评测指标。
- 右侧在桌面端保持可见；不会遮挡内容，也不会在窄屏强制双栏。

### 技术身份

Package hash、评测套件等低频字段放入默认折叠的“技术身份与版本凭据”。
证据详情保持在页面下方，能力不可用时继续显示原有明确说明。

## 中文文案规则

- 普通操作和状态全部使用中文。
- Package、Agent、Release、Grounded 等协议名可保留，但必须附带中文语义。
- 原始策略值、模型能力名和 hash 不翻译，作为技术值展示。
- 评测指标使用固定中文映射；未知指标保留原键，避免丢失数据。

## 响应式与可访问性

- 桌面端主栏与状态栏比例约为 2:1，所有 grid 子项允许收缩。
- 760px 以下改为单列：状态摘要先于工具，指标横向分组或纵向排列。
- 长 Agent ID、hash 和策略值必须安全换行，不扩大页面宽度。
- 保留表单 label、状态 live region、键盘焦点和 reduced-motion 规则。
- 交互 ID 与事件绑定不变，确保搜索和对话功能不因布局重排失效。

## 边界

本次不修改后端、鉴权、共享 Token、Package 内容、Agent 版本、模型选择、检索算法、
证据审计 v2 工作区或发布协议。证据审计 v2 继续使用独立审计布局。

## 验收

- Agent v1 页面不再以 package slug 作为主标题，首屏中文化。
- 桌面为工作区与状态栏双栏；手机为单列且没有横向页面滚动。
- 版本、评测、模型、检索、升级、指标和技术身份均可找到。
- 搜索与循证对话仍使用现有 API、状态反馈和防重复提交机制。
- Package、Book App 与证据审计 v2 视图不发生结构性回归。
