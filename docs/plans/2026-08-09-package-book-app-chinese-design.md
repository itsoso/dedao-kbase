# 包契约与阅读应用中文化设计

## 背景

Agent 控制台已完成中文化，但同一 Package 的“包契约”和“阅读应用”仍共用一套
英文优先模板。页面同时展示大量版本、策略、评测和证据内容，却没有区分管理者
查看契约与读者使用知识的两种任务，导致信息层级不清晰。

## 目标

- 两个页面的导航、标题、状态、操作和辅助说明均使用中文。
- 包契约页聚焦版本、运行边界、可信评测和技术凭据。
- 阅读应用页聚焦阅读、检索、循证问答和证据账本。
- Package、Release、Claim、Citation、Agent ID、哈希等技术身份保持原值，避免破坏审计链。
- 桌面端建立清晰分栏，390px 手机端保持单栏且没有横向溢出。

## 方案

### 共用产品语言

继续沿用 Agent 控制台的深墨绿、纸张白与荧光绿视觉系统，但两个页面使用不同的
信息组织：包契约是“管理与审计面”，阅读应用是“研究与操作面”。共用中文术语
映射，避免同一策略值在不同页面产生不同译法。

主要映射：

- `reasoning` → `推理模型`
- `lexical` → `关键词检索`
- `human_review` → `人工复核`
- `standard` → `标准使用策略`
- `Evaluation passed` → `评测通过`
- `Evaluation hold` → `评测待通过`

技术原值放在代码样式或折叠凭据中；产品级标签不再混排英文。

### 包契约页

顶部使用可读的 Agent 中文名称，而非裸 Package ID。主摘要展示当前版本、固定
Release 数、使用策略和评测状态。主体采用“契约摘要 + 可信评测”双栏：左侧解释
模型路由、检索方式、人工升级和证据边界；右侧展示中文评测指标。

Package hash、Release ID、内容哈希、评测套件等进入默认折叠的“技术身份与版本
凭据”。页面仍提供跳转到 Agent 控制台和阅读应用的中文导航，但不重复阅读应用的
完整交互工作区。

### 阅读应用页

顶部展示“阅读研究台”和书籍中文标题，清晰说明知识范围固定在当前版本。主体采用
主要工作区与右侧版本状态栏：主要工作区依次提供版本化阅读、包内检索和循证问答；
状态栏展示当前版本、评测状态、引用要求和拒答边界。

证据账本位于工作区之后，保留 Release、Claim 与 Citation 的原始身份。详细 Package
哈希和策略原值进入折叠区，降低首屏技术噪音。

### 状态与错误

加载、检索、问答、拒答和缺少 Release/book_id 的既有行为保持不变。中文化只改变
表达和布局，不改 API、路由、请求参数或可信边界。长 Package ID、Release ID 和
Citation ID 必须允许任意位置换行。

## 验收

- 两个路由不再出现面向用户的 `PACKAGE CONTRACT`、`SHARED BOOK APP`、
  `Reader`、`Grounded search`、`Open the book`、`Evaluation passed` 等英文文案。
- 两个页面具有不同且明确的中文信息架构，而不是共用一份完全相同的主体。
- 搜索与循证问答继续使用原有表单和状态绑定。
- 桌面端分栏成立；390px 下为单栏，真实长技术 ID 不造成横向滚动。
- 现有 Agent 控制台、v2 证据审计页和 API 契约不受影响。
